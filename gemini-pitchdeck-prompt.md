## Prompt

```
I have a pitch deck web app for "Reach" — a local services marketplace for Nigeria with on-chain Solana escrow. It was generated by Bolt.new and follows a specific Cloudflare-inspired design system. I'm pasting the code below.

Refine and polish this deck. The design language is: clinical Cloudflare product-announcement style. White and near-black (#0F172A) alternating slide backgrounds. Inter for all text, JetBrains Mono for labels/tags/numbers. Orange (#EA580C / #F97316) used ONLY for small-caps labels, numbered markers, and the final slide's accent word. Content in modular grid cards, never bullet lists. Every slide follows this hierarchy: orange monospace label → bold headline stating the takeaway → card grid → muted one-line summary at the bottom. Generous whitespace. No decoration for decoration's sake.

Here's what to do:

## 1. ENFORCE THE DESIGN SYSTEM CONSISTENTLY

Go through every slide and verify:
- The orange monospace label sits at the same Y position on every slide (top area, consistent padding)
- The bold headline sits at the same Y position on every slide
- The bottom summary line sits at the same Y position on every slide
- Card grids are vertically centered in the remaining space between headline and summary
- Card padding, border-radius (rounded-lg), and internal spacing are identical across all slides
- Numbered markers (01, 02, 03...) in JetBrains Mono bold orange are left-aligned to card titles consistently
- The thin bottom bar/progress strip is present on every slide at the same position
- Dark slides (#0F172A) use white text for headlines, slate-400 for body, orange for labels
- White slides use #0F172A for headlines, slate-500 for body, orange-600 for labels
- Fix any inconsistency. The deck should feel like one designed artifact, not a collection of separate pages.

## 2. TYPOGRAPHY PRECISION

- Headlines: Inter, font-bold, text-3xl to text-4xl (30-38px), tracking-tight (-0.025em)
- Labels: JetBrains Mono, font-bold, text-xs (11px), uppercase, tracking-[0.2em]
- Card titles: Inter, font-bold, text-base to text-lg (16-18px)
- Card descriptions: Inter, font-normal, text-sm (14px), text-slate-500
- Stat numbers: Inter, font-bold, text-5xl to text-6xl (48-60px)
- Monospace badges/pills: JetBrains Mono, font-bold, text-[10px] to text-xs, uppercase
- Slide numbers: JetBrains Mono, text-xs, text-slate-500
- Ensure line-height is generous on body text (leading-relaxed) and tight on headlines (leading-tight)

## 3. CARD COMPONENT EXTRACTION

Extract a reusable card component used across slides 2-9. Props:
- `number` (optional): "01", "02", etc. — rendered in JetBrains Mono bold orange
- `icon` (optional): small icon in a subtle circular container
- `title`: Inter bold, near-black or white depending on slide background
- `description`: Inter regular, muted gray
- `badge` (optional): status pill ("DOWN", "HEALTHY", "ACTIVE LEADER", etc.) with color variant
- `variant`: "light" (slate-50 bg) or "dark" (slate-800 bg) depending on slide background

This prevents style drift between slides.

## 4. ANIMATIONS — MINIMAL AND PURPOSEFUL

Keep it restrained. Cloudflare decks don't bounce or scale.
- Slide transitions: cross-fade only, 200ms ease-out, opacity transition
- Card entry: fade-in + translate-y (from 8px below), staggered by 60ms per card, 300ms duration
- Stat numbers on slide 6: count-up animation from 0, triggered on slide entry, 800ms ease-out
- Revenue percentages on slide 7: same count-up treatment
- Roadmap milestones on slide 9: sequential fade-in left-to-right, 100ms stagger
- NO parallax, no scale transforms, no blur transitions, no rotation
- Respect prefers-reduced-motion: disable all animations when enabled

## 5. RESPONSIVE CONSIDERATIONS

The deck is primarily for 16:9 desktop presentation, but:
- Set a max-width (1280px) and center content horizontally for ultra-wide monitors
- Card grids should not break to single-column — maintain the grid at all reasonable widths
- Text should not overflow or wrap awkwardly at 1024px width minimum
- Slide content should be vertically centered in the viewport

## 6. INTERACTION & NAVIGATION

- Arrow keys: left/right to navigate slides
- Slide number display: bottom-right, "3 / 10" format, JetBrains Mono, muted
- Progress bar: thin (2-3px) horizontal line at the very bottom edge, orange fill proportional to position
- Click/tap: left third of screen = previous, right two-thirds = next
- No other UI chrome. No hamburger menus, no toolbars, no floating buttons.

## 7. NARRATIVE & COPY REVIEW

Review every slide's text and tighten it:
- Headlines state the INSIGHT, not the category. "Money Moves on Hope." not "Problem Statement"
- Card descriptions are one sentence, max two. No jargon that needs explanation.
- Stats are specific: "₦4T+" not "billions", "#1 in Africa" not "high adoption"
- The overall arc should feel inevitable: Problem → Pain is real → Solution exists → It's built → Market is massive → Revenue is clear → Execution is underway → Join us
- Tone: confident, precise, technical-enough-to-impress but never alienating. A smart investor who doesn't know crypto should follow every slide.

## 8. CODE QUALITY

- Extract shared layout wrapper component (handles dark/light variant, consistent padding, label/headline/summary positions)
- No inline styles — everything in Tailwind utilities or extracted @apply classes
- All animations via CSS transforms (GPU-accelerated), never top/left/margin animations
- Clean component structure: App → SlideContainer → individual Slide components
- Type the slide data as a const array if possible (title, label, summary, variant, content)

## 9. PRINT / EXPORT

- Add @media print stylesheet:
  - Each slide renders as a single page (page-break-after: always)
  - Hide navigation, progress bar, and slide numbers
  - Force white backgrounds for readability (or maintain dark slides as-is for contrast)
  - Ensure all text is visible and not clipped
  - This enables Ctrl+P → Save as PDF for a static handout version
```
